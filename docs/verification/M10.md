## M10-A 传输无关分派 · 已完成

- `CliControlServer` 新增公开方法 **`dispatch(request)`**：HTTP CLI 与 JSON-RPC 共用同一个命令分派器（主进程命令 + 转交渲染进程），不存在第二套业务逻辑。
- `CliServerInfo` 增加可选 `rpc: { tcpPort, pipePath }`；服务启动后 `attachJsonRpc()` 重写发现文件 `userData/cli/server.json`，Agent 只读一个文件就能拿到两条入口。
- 纪律检查放宽：`scripts/check-env.mjs` 不再全仓禁 `node:net`，改为**只允许 `src/main/`**（本地回环控制面），其余位置使用即报错。

## M10-B JSON-RPC 2.0 行协议 · 已完成

| 项 | 口径 |
|---|---|
| 分帧 | 一行一个 JSON 对象；`\n` / `\r\n` 都吃；跨块自动拼接 |
| 鉴权 | **每个连接首行必须是 `auth`**，token 恒定时间比较；未认证前只允许 auth，失败即断开 |
| 方法 | `version`（capabilities）、`commands.list`、`auth`，以及 `CLI_COMMANDS` 里的**任意命令名**（如 `project.get` / `clip.add` / `export.start`） |
| 顺序 | 单连接串行执行，响应顺序可预测（Agent 不需要自己排序） |
| 错误 | JSON-RPC 错误对象 + `data.code` 保留 Socut 稳定错误码（`BAD_PARAMS` / `NOT_FOUND` / `GATE_BLOCKED`…） |
| 传输 | `tcp://127.0.0.1:<随机端口>` + `\\.\pipe\socut-<pid>`（Unix 为 `/tmp/socut-<pid>.sock`） |
| 保护 | 单行 ≤ 32MB（帧图 base64 在同一行返回）、最多 8 个连接、TCP 只绑回环 |
| 生命周期 | 与 CLI 服务同启停（`main/index.ts`）；`server.json` 里带两个入口 |

**纯函数层** `src/shared/jsonRpc.ts`（不 import Node/Electron）：请求解析、响应构造、错误码映射、分帧，主进程/测试/将来的 MCP 适配层共用。

## M10-C 项目锁 · 已完成（模块 + CLI/RPC 命令）

- `src/main/projectLock.ts`：锁文件 = `<工程绝对路径>.lock`；内容含 token / pid / mode / 心跳。
- 陈旧判定：**心跳 > 15s 未更新 或 持有进程已退出** → 可接管（崩溃残留不会锁死工程）。
- 心跳 5s 自动续期（timer unref，不阻止退出）；release 只在 token 匹配时删文件（A 不能删 B 的锁）。
- 原子写：临时文件 + rename，避免读到半截 JSON；坏文件按"无锁"处理。
- CLI / JSON-RPC 命令：`project.lock { path, mode }` / `project.unlock { path, token }` / `project.lockStatus { path }`。

## M10-D 取帧 preview.frame · 已完成

## M10-F 事件流 `events.subscribe` · 已完成（导出进度 + 工程变更）

让 Agent 用**长连接订阅**替代轮询 `export.status`。事件只走 JSON-RPC（HTTP CLI / MCP 不新增工具）。

### 协议形状

```jsonc
// 1) 订阅（认证后；返回确认 + 当前可用主题）
{"jsonrpc":"2.0","id":1,"method":"events.subscribe","params":{"topics":["export.progress"]}}
{"jsonrpc":"2.0","id":1,"result":{
  "ok":true,"subscribed":["export.progress"],"topics":["export.progress"],
  "available":["export.progress","project.changed"],"limit":32,"nextSeq":1
}}

// 2) 服务端主动推送：**无 id 的 notification**（客户端不能按 id 配对）
{"jsonrpc":"2.0","method":"event","params":{"topic":"export.progress","data":{"jobId":"…","phase":"rendering","framesDone":42,"framesTotal":300,"outTimeUs":0,"percent":0.14,"bytesWritten":0,"elapsedMs":1200,"notices":[]},"seq":1}}

// 3) 退订（省略 topics = 全部退订；未知/未订阅主题忽略）
{"jsonrpc":"2.0","id":2,"method":"events.unsubscribe","params":{"topics":["export.progress"]}}
{"jsonrpc":"2.0","id":2,"result":{"ok":true,"unsubscribed":["export.progress"],"topics":[]}}
```

| 项 | 口径 |
|---|---|
| 主题 | `export.progress`、`project.changed`（登记在 `src/shared/jsonRpc.ts` 的 `EVENT_TOPICS`；`available` 原样返回，客户端不猜名字） |
| `export.progress` 数据 | 与 `export.status` 的 job 快照**同口径**（`JobProgress`：jobId/phase/framesDone/framesTotal/outTimeUs/percent/bytesWritten/elapsedMs/notices），来自 `ExportEngine.onProgress()`；节流与渲染侧 `job:progress` 共用 100ms ticker，终态 done/failed/cancelled 各推一次 |
| `project.changed` 数据 | `{ path, name, reason, revision, mode?, at }`；`reason ∈ {new, open, openRecent, save, lock, unlock}`。主进程可观测点：CLI `project.new/open/openRecent`（当前工程路径切换）、渲染侧 `project.save` 成功（落盘路径）、`project.lock/unlock`（工程锁变化） |
| `revision` | 恒为 `null`：主进程没有干净的 revision 观测点（唯一真值是渲染进程 zustand store，自动保存 IPC 也不带 revision）。**不臆造**版本号；将来窗口侧/自动保存接线后可填真值 |
| `seq` | 每连接从 1 递增；**被丢弃的事件也占号**（跳号 = 背压丢过事件） |
| 订阅上限 | 单连接最多 **32** 个主题（`MAX_EVENT_SUBSCRIPTIONS`，可被 `options.maxSubscriptions` 覆盖）；超限错误码 **-32008**、`data.code = EVENT_SUBSCRIPTION_LIMIT` |
| 参数错误 | 未知主题 / `topics` 不是非空字符串数组 → **-32602**（`data.code = BAD_PARAMS`，`detail` 列出可用主题） |
| 能力声明 | `auth` / `version` 的 `capabilities` 追加 `events` |
| 断连清理 | socket close 即清空该连接的主题表、待发队列，并从事件分发表移除 |
| 背压 | ① 每连接待发事件**有界队列**（默认 256，满了丢最旧）；② socket 待发字节 > 256KB 先等 `drain`；③ 丢弃体现为 seq 跳号 |

### 实现落点

- `src/shared/jsonRpc.ts`：主题表/notification 构造/`BoundedEventQueue`/`ControlEventBus`（进程内单例 `controlEventBus`）+ `projectChangedEvent()` 纯函数。
- `src/main/control/jsonRpcServer.ts`：`events.subscribe` / `events.unsubscribe` 处理、按连接主题表分发、有界队列 + drain 背压、断连清理、`eventDiagnostics()`（测试/诊断用）。
- `src/main/export/engine.ts`：`onProgress(listener)` 钩子；`remember()` 与 done/failed/cancelled 终态各推一次快照；**监听器抛错一律吞掉**（事件 bug 不能让导出失败）。
- `src/main/cliServer.ts`：`start()` 把 engine 进度 publish 到总线、`stop()` 解除；CLI 工程命令/工程锁处 publish `project.changed`。
- 不需要改 `main/index.ts`：事件源是协议模块里的进程内总线（业务侧 publish、控制面订阅），测试用 `options.events` 注入独立总线。

## M10-G 窗口侧工程锁接线 · 已完成

补上 M10 最后一个"模块有、窗口没接"的缺口。

| 件 | 内容 |
|---|---|
| 模块 | `src/main/windowProjectLock.ts`：`createWindowProjectLock()` → `bind(path)/release()/currentPath()`；同一时刻窗口只持一把锁，换工程时**先释放旧锁再拿新锁**（否则旧工程对 Agent 永远显示"占用中"）；同一路径重复 bind 幂等（不重置 token/心跳） |
| 持锁时机 | `project:open`（对话框打开）、`project:recentOpen`（启动页打开）、`project:saveAs`、`project:writeToPath`（CLI 指定路径保存）成功后立即 `bind`；`project:recentCreate`（新建）释放 |
| 释放时机 | `app.on('will-quit')` 释放；即使来不及释放，心跳停止 15s 后被判陈旧，下一次打开自动接管（`projectLock.ts` 既有口径） |
| 冲突策略 | **窗口侧不阻止用户打开工程**：Agent 已持新鲜锁时 `bind` 返回 `locked`，只写一行 warn 日志并退回"无锁"旧行为；用户可见的拒绝在 Agent 侧（`project.lock` 报 `工程已被占用（pid N，window）`） |
| 与事件流 | 锁变化仍由 CLI 侧的 `project.changed {reason:"lock"/"unlock"}` 发布（M10-F）；窗口侧持锁不额外发事件（避免与 `project.changed` 的语义重复） |
