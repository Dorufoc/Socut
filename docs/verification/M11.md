## M11-A SRT / ASS 解析与生成 · 已完成

`src/shared/subtitleFormats.ts`（纯函数，主进程与渲染进程共用）：

| 能力 | 口径 |
|---|---|
| `parseSrt` | 宽容：BOM / CRLF / 缺序号 / 毫秒用点号 / 多行文本；`<i>` 等标签剥掉；时间倒挂·空文本·无时间码块记 `dropped` |
| `parseAss` | 只取 `[Events]` 的 `Dialogue` 行；剥掉 `{\...}` 覆盖标签；`\N` 还原换行 |
| `parseSubtitleFile` | 自动识别：含 `[Events]`/Dialogue 走 ASS，否则 SRT |
| `formatSrt` / `formatAss` | 生成可被 Premiere/Resolve 导入的文本；ASS 带最小 `[Script Info]/[V4+ Styles]/[Events]` 结构 |
| `cuesFromClips` | 工程字幕条 → cue（标题+副标题换行拼接，按时间排序，空条目跳过） |

> 修掉的解析 bug：SRT 结束时间码带前导空格时 `split(/\s+/)[0]` 取到空串，导致**整批 cue 被丢**（真机测试抓到的）。

- 输入三种形态：**CSV/TSV**（标题,副标题,时长；表头自动跳过，支持引号与 `""` 转义）、**JSON**（字符串数组 / `{title,subtitle,durationSec}` 数组 / `{rows:[...]}`）、**纯文本**（一行一条）；

## M11-E 资产分发 + 真机转写 · 已完成（第三批）

网络恢复后按 `npm run fetch:whisper` / `npm run fetch:whisper:model` 拉到了真资产，并把
"真二进制 + 真模型 + 真音频"跑通；**假 sidecar 测不出来的问题一次抓出 4 个**：

| # | 真机问题 | 假 sidecar 为什么测不出 | 修法 |
|---|---|---|---|
| 1 | whisper.cpp 默认**不打印进度**，`progress = X%` 永远不出现 → 进度条纹丝不动 | 假 sidecar 自己 `stderr.write` 了进度行 | `buildWhisperArgs` 补 `-pp`（与 `-np` 可共存），并有真实断言 `进度最大值 = 100` |
| 2 | 原生 JSON 的 `offsets` 是**数字毫秒**（`"to": 5500`），旧实现当秒 → 8s 音频的 cue 变成 5500s | 夹具把 offsets 写成了**字符串** `"5500"` | `parseMilliseconds`（数字/数字串/时间码）与 `parseSeconds` 分开，按单位明确取值 |
| 3 | 官方 Windows 构建的 whisper-cli **只读 16k 单声道 WAV**，喂 mp4 直接 `failed to read audio data as wav`（且**退出码仍是 0**，只是不产 JSON） | 假 sidecar 不看输入格式 | 转写前用随包 FFmpeg 抽 `-ac 1 -ar 16000 -c:a pcm_s16le` WAV；失败抛 `WHISPER_AUDIO_FAILED`；`WhisperManagerOptions.ffmpegPath` 支持惰性解析 |
| 4 | 自动语言检测把中文短视频识别成英文（`-np` 那次输出 "Today, the voting report…"） | 夹具直接给 `language: 'zh'` | 文档口径：中文素材请显式给 `-l zh`（CLI/MCP 的 `language` 字段），自动检测只做兜底 |

顺带修掉一个**偶发红**：假 sidecar 两条进度写在同一 chunk 时，主进程按"取最后一条"只会报 100，
`expect(progress).toContain(40)` 随机失败（之前那次 `verify` 的 "1 failed / 1480 passed" 就是它）。
现在假 sidecar 两条进度间隔 80ms，断言稳定。

## M11-F 渲染侧「自动字幕」入口 · 已完成（第四批：UI 接线）

目标链路：**选中媒体片段 → 点「自动字幕」→ 看进度/可取消 → 字幕条落到时间轴**。

| 件 | 内容 |
|---|---|
| IPC | `caption:transcribe`（invoke）：参数 `{requestId, mediaPath, language?, modelPath?}`，返回 `{ok, cues, language, errorCode, errorMessage}`——**错误不抛异常**，错误码原样透传（`WHISPER_BINARY_MISSING` / `WHISPER_MODEL_MISSING` / `WHISPER_MEDIA_MISSING` / `WHISPER_AUDIO_FAILED` / `CANCELLED` 等）；`caption:progress`（主进程→渲染侧，`{requestId, percent, stage}`）；`caption:cancel`（按 requestId 取消） |
| 主进程会话层 | `src/main/captionTranscribe.ts`：requestId → AbortController 会话表、进度归一（prepare 0% → transcribe X%，夹到 0..100）、错误码原样透传、取消统一 `CANCELLED`、同 requestId 在跑时 `CAPTION_BUSY` 拒绝并发 |
| 接线 | `src/main/ipc.ts`：懒创建 whisper 管理器（与 CLI 共享 `userData/whisper.json` 配置；随包 FFmpeg 抽音），进度只发给发起请求的窗口，窗口销毁后忽略 |
| 渲染 API | `src/preload/index.ts` + `src/shared/api.ts`：`window.socut.caption.transcribe / onProgress / cancel`（类型安全，零 Node 泄露） |
| 面板 | 字幕列表上方新增「自动字幕」按钮 + 识别语言（中文默认 / 英文 / 自动检测）：未选中媒体片段时**禁用并常驻提示**；识别中显示进度条与「取消识别」；成功后落时间轴并提示「新增 N 条」；失败展示错误原文 + 可执行提示（导入二进制/模型、重新定位素材、抽音失败原因） |
| 时间映射 | `src/renderer/src/panels/captionAuto.ts`：`timelineSec = timelineStartSec + (cueSec - sourceInSec) / speed`（变速按倍速换算，不能写成只对 1x 成立的 `timelineStartSec - sourceInSec`），再裁到片段窗口 `[timelineStartSec, timelineEndSec]`；完全在窗口外 / 空文本 / 裁剪后无正时长的 cue 丢弃 |
| i18n | `TEXT.captions.autoCaption*` 中文文案（按钮/语言档位/进度/取消/成功/空结果/错误/可执行提示），面板不写裸字符串 |
| 落库 | 复用 store `addCaptionsFromCues(cues, {replace:false})`——与 SRT/ASS 导入同一条落库路径 |

**口径**：转写针对**整份媒体文件**（不预先切片段音频）；面板只把与当前片段窗口重叠的 cue

## M11-H 抽音阶段真实进度 · 已完成

原问题：自动字幕进度条在「准备音频…」阶段一直停在 0%，长素材看起来像卡死（转写还没开始）。

| 件 | 内容 |
|---|---|
| FFmpeg 进度 | 抽音命令追加 `-nostats -progress pipe:1`；解析 `out_time_us`（微秒）/ `out_time_ms`（**也是微秒**，FFmpeg 历史命名遗留）/ `out_time=HH:MM:SS.ffffff` 三种形式 |
| 时长 | 新增 `ffprobePath` 依赖（主进程与 CLI 都用随包 `ffprobe` 读 `format=duration`）；读不到时长时抽音进度退化为"只有在 0%"，不臆造 |
| 百分比 | `percent = clamp(outSec / duration * 100, 0, 99)`：**抽音阶段最多 99%**，100% 留给转写，避免进度条先满后回退；同值不重复上报 |
| 会话层 | `captionTranscribe` 服务把 `onPrepareProgress` 包成 `stage: 'prepare'` 事件（与 transcribe 阶段分开），渲染侧进度条自然推进 |
| 取消 | 仍走原 AbortSignal → kill 子进程；抽音进程被 kill 时错误码仍是 CANCELLED（既有口径未变） |

## M11-I 字幕批量编辑 UI · 已完成（第七批：列表多选）

目标：字幕列表支持多选，并对选中集合做批量操作；**每个批量动作 = 一次 revision（一步撤销）**，
不是循环 N 次写库。不改导出/渲染管线，只动字幕数据与列表 UI。

| 件 | 内容 |
|---|---|
| store 批量入口 | 新增 5 个：`applyPresetToClips / setClipsDuration / removeClips / setClipsCompact / setClipsGradientEnabled`。全部先在内存里算完整批，最后只调一次 `set({ project, revision+1 })`；同值 / 未知 id / 非法时长不写、不推 revision；返回实际改写条数 |
| 批量预设 | 与单条切预设同义（`clipWithPresetDefaults`：清自定义、字体回默认、动画回预设节奏），文字内容与入出点保持不动 |
| 统一时长 | 每条从**自己的入点**顺延到「入点 + N 秒」；`snapTimeToFrame` 吸附帧边界、不小于 `MIN_CLIP_DURATION_SEC`；撞到右侧邻居就贴住，夹完不足最短时长的条目保持原样（不制造非法区间） |
| 两个开关 | 「强制竖屏紧凑」（`styleOverrides.compact`，关掉删键，不留假自定义）与「标题渐变」（主/副标题一起开关：开走已有颜色、缺省白 #ffffff→浅蓝 #9ec7ff 90°；关只翻 enabled 保留颜色） |
| 批量删除 | 未知 id 忽略；删掉的正是当前选中条目时，选中态挪到剩余第一条，绝不留下指向已删片段的 `selectedClipId` |
| 面板 | 标题栏「批量」进入多选；卡片点击语义从「选中 + 跳中点」变为「勾选」；工具栏：已选 N 条 / 全选 / 清空 / 预设 / 统一时长 / 两个开关 / 删除选中；未勾选时按钮禁用并常驻提示 |
| 多选状态 | 只在组件本地 `useState`（不进 uiStore、不落工程）；切换单条选中、切换序列、退出批量时清空 |
| i18n | `TEXT.captions.batch*` 与 `selectNamed` 中文文案，面板不写裸字符串 |

**一次撤销步怎么保证**：批量 action 对 N 条只做一次 `set({ project, revision+1 })`，
项目级历史（`projectHistory`）按 store 变更记账，所以整批只压一步；测试直接断言
「3 条一起改预设 → `past` 长度 1 → undo 后 3 条一起回滚」。

**取证**

```
npx vitest run src/renderer/src/state/captionBulk.store.test.ts src/renderer/src/panels/CaptionListPanel.test.tsx
# 13 + 21 = 34 例全绿
#   store 13：批量预设（改写条数/同值/未知 id）/ 统一时长（吸附帧/邻居夹取/非法值/同值）/
#             批量删除（选中迁移/空与未知）/ 紧凑开关（删键/同值）/ 渐变开关（缺省双色/保留自定义颜色/同值）/
#             一次撤销步
#   面板 21：既有 14 + 新增 7（进入批量与勾选语义 / 批量预设 / 统一时长吸附帧 / 批量删除 /
#             切换选中清空 / 紧凑开关往返 / 未勾选禁用提示）
```
