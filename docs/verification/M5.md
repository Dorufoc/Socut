## M5-B 波纹删除与相邻合并 · 已完成

**新增纯函数**：`src/shared/timelineOps.ts`

| 函数 | 语义 | 关键约束 |
|---|---|---|
| `rippleDeleteMediaClip(clips, id, fps)` | 删该段，并把**同轨**位于其后的片段整体左移其时长 | 异轨不动；`snapTimeToFrame` 帧对齐；变速段按时间轴时长位移（不是源窗口） |
| `canMergeMediaClips(left, right, fps)` | 合并前置判定 | 同轨、相邻（半帧容差）、同素材、同倍速、源连续（`right.sourceIn == left.sourceOut`）、画面/防抖/音频参数一致；失败返回稳定 reason |
| `mergeMediaClips(clips, ids, fps)` | 合并两段 | 沿用左段 id 与参数；右段内部切点的 `transitionIn` 丢弃；左段入场转场保留；结果按时间轴排序 |
| `nextMediaClipOnTrack` / `previousMediaClipOnTrack` | 同轨邻段查找 | 按起点排序，跳过异轨 |
| `isClipDurationValid` | 最短媒体时长校验（UI 提示用） | `MIN_MEDIA_CLIP_SEC` |

**store 接线**：`src/renderer/src/state/projectStore.ts`
- `rippleDeleteMediaClip(id)`：锁定轨拒绝；转场/选中态清理；防抖代理缓存回收；`revision + 1`（撤销一步）。
- `mergeMediaClipWithNext(id)`：无下一段/不可合并返回 false；合并成功接管选中态。

**UI 入口**
- `Shift+Delete`：媒体段选中时走波纹删除（`src/renderer/src/hooks/useDeleteSelected.ts`）。
- `Ctrl/Cmd+M`：与同轨下一段合并（`src/renderer/src/App.tsx`）；失败给 `TEXT.timeline.noMergeTarget` 提示。

**CLI 入口**：`timeline.media.rippleDelete`、`timeline.media.mergeNext`（`src/shared/cliProtocol.ts` + `src/renderer/src/cli/commandRouter.ts`）。

**取证**
```
npx vitest run tests/timelineOps.test.ts src/renderer/src/state/rippleMerge.store.test.ts src/renderer/src/hooks/useDeleteSelected.test.tsx
# 3 files / 30 tests 全绿（纯函数 13 + store 8 + 键盘 9）
npm run verify
# check:env + eslint + typecheck(node/web/tests) + vitest 84 files / 1240 tests 全绿
```

**口径说明**
- 波纹删除只合拢**被删片段自身占用的间隙**（后续同轨片段左移固定时长）；若要“所有轨全部左移贴合”用既有的「主轨对齐」`snapTogether`（`compactMediaClips`）。
- 合并要求两段参数完全一致：调色/防抖/音量不同的两段合并会静默丢参数，因此一律拒绝并给原因。

## M5-C 冻结帧 · 已完成

**口径**：冻结帧不改 `MediaClip` 结构，而是「源视频某一时刻抽一帧 → 全分辨率 PNG → 作为普通 image 素材入池 → 切点处插入该静帧片段，后续同轨片段右移」。这样导出侧直接走既有的 `-loop 1 -t` 图像链路，不需要给 ffmpeg 图新增分支。

| 环节 | 位置 | 说明 |
|---|---|---|
| 抽帧 argv | `src/shared/ffmpegArgs.ts` `buildFreezeFrameArgs` | `-ss` 放在 `-i` **之后**（先解码再 seek，要的是时间轴对齐的那一帧）；单帧、无缩放、无音频流 |
| 落盘路径 | `src/main/paths.ts` `userFreezesDir/userFreezePath` + `USER_DATA_DIRS.freezes` | `userData/freezes/<素材>-<毫秒>.png`；按前缀回收 |
| 主进程抽帧 | `src/main/freezeFrame.ts` `extractFreezeFrame` | 源不在 / FFmpeg 缺失 / 失败一律 `path:null`（不抛错）；`removeFreezeFrames` 按前缀清理 |
| IPC | `CHANNELS.mediaExtractFrame` + `src/main/ipc.ts` | 同时把 `mediaThumbRemove` 扩成「缩略图 + 预览条 + 频谱 + 冻结帧」一并回收 |
| 纯函数计划 | `src/shared/timelineOps.ts` `planFreezeFrame` | 左段 + 冻结段 + 右段首尾相接；右段不继承原入场转场；后续同轨片段右移固定时长；切点吸附帧边界 |
| store 动作 | `src/renderer/src/state/projectStore.ts` `freezeFrameAt` | 目标解析 = 显式 clipId → 选中段 → 播放头处最上层**可见**媒体轨；锁定轨拒绝；抽帧 → 入池 → 插入，选中态落冻结帧 |
| CLI | `timeline.media.freeze` | `{ at: number, id?: string, duration?: number }` |
| 快捷键 | `Shift+F` | 播放头（或预览黄线）位置插入，失败给 `TEXT.timeline.noFreezeTarget` 提示 |

**取证**

```
# 纯函数 + argv + store（35 例）
npx vitest run tests/timelineOps.test.ts tests/freezeFrameArgs.test.ts src/renderer/src/state/rippleMerge.store.test.ts
# 3 files / 35 tests 全绿（planFreezeFrame 6 例、argv 5 例、store 4 例）

# 真机抽帧（与 buildFreezeFrameArgs 同 argv 形状）
ffmpeg -hide_banner -y -loglevel error -i src.mp4 -ss 1.000000 -frames:v 1 -an -sn -dn freeze.png
ffprobe → 1280x720 rgb24，PNG 157,779 bytes   # 通过
```

**边界**
- 抽帧失败（源被移动 / FFmpeg 缺失）不改工程，只提示；
- 切点距两端不足 `MIN_MEDIA_CLIP_SEC` 拒绝；轨道锁定拒绝；隐藏轨不参与目标解析；
- 冻结片段默认 1s（`FREEZE_FRAME_DEFAULT_SEC`），可通过 CLI `duration` 指定；
- 抽帧产物是运行时派生文件，不进工程 JSON；素材移出素材池时按 mediaId 前缀整批回收。

## M5-D 多序列（一个工程多段剪辑）· 已完成

**核心口径（避免"双份真相"）**：活动序列的内容就是 `Project` 的平铺字段（`clips`/`mediaClips`/`mediaTracks`/`audioTracks`/`subtitleTrack`），
`Project.sequences` 只存**非活动序列快照**。因此预览、导出、CLI、423 处既有读取点全部零改动，
切序列 = 平铺字段打包成快照 → 把目标快照摊回平铺字段。

| 项 | 位置 | 说明 |
|---|---|---|
| 类型 | `src/shared/types.ts` `SequenceSnapshot`、`Project.sequences/activeSequenceId/activeSequenceName` | 快照与活动序列同形；`graphicsZ` 为 M7 预留 |
| 常量 | `src/shared/constants.ts` | `PROJECT_VERSION 3→4`、`DEFAULT_SEQUENCE_ID='seq-main'`、`DEFAULT_SEQUENCE_NAME='主序列'`、`MAX_SEQUENCES=20` |
| 纯函数 | `src/shared/sequence.ts` | `activeSequence` / `allSequences` / `sequenceSummaries` / `switchSequence` / `addSequence` / `removeSequence` / `renameSequence` / `duplicateSequence`；默认 id/名字不落盘 |
| schema | `src/shared/projectSchema.ts` | `normalizeSequenceSnapshot`：非活动序列逐个归一（轨道/片段/响度/序列名），丢弃缺 id / 与活动序列 id 重复 / 非对象项，总数夹到 `MAX_SEQUENCES`；单序列工程不写三个序列键（JSON 与 v3 逐字节一致） |
| store | `src/renderer/src/state/projectStore.ts` | 5 个 action；切换/删除活动序列时清空选中态（片段 id 属于旧序列） |
| UI | `src/renderer/src/timeline/Timeline.tsx` + `styles.css` | 工具栏右侧「序列」下拉 + 新建/删除按钮；只剩一条时删除禁用并给 title 说明 |
| CLI | `sequence.list / add / select / rename / remove / duplicate` | 全部返回最新 `sequenceSummaries`；错误映射 `NOT_FOUND`/`BAD_PARAMS` |

**迁移**：v3→v4 是**纯加法**——不搬动任何片段数据，旧工程打开后自动落到默认序列 `seq-main`；
`normalizeProject` 永远写回 `version: 4`，单序列工程序列键缺省不出现。

**取证**

```
npx vitest run tests/sequence.test.ts src/renderer/src/state/sequence.store.test.ts tests/projectSchema.test.ts src/renderer/src/timeline/Timeline.test.tsx
# 4 files / 152 tests 全绿

#   store 6 例（切换清空选中态、切回片段完好、删活动序列回退）
#   Timeline 45 例（含 3 例序列工具栏：新建/切换/删除）
npm run verify
# 全绿（见本轮报告）
```

**边界**
- 素材池是工程级共享的（切换序列不复制素材）；
- 序列名 trim + 限长 40；空名忽略；达到 20 条上限新建/复制返回 null；
- 删活动序列会自动切到第一条非活动序列；只剩一条时拒绝；
- 切序列是一次工程变更（revision +1，自动存档；撤销可回到上一个序列）。
