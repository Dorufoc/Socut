## M8-B 变声 · 已完成

`voiceChangeFilters(kind)`：

| 档位 | 滤镜链 | 时长 |
|---|---|---|
| chipmunk | `rubberband=pitch=1.3` | **1:1** |
| deep | `rubberband=pitch=0.8` | **1:1** |
| robot | `vibrato=f=10:d=0.8` + `tremolo=f=25:d=0.9` | 1:1 |

**数据**：`ClipAudio.voiceChange`；UI 与 CLI 同上。

## M8-D 手绘遮罩（mask）· 已完成（第三批：预览 + 导出同源）

目标：在预览画面上直接涂抹"哪里可见/哪里抹掉"，预览实时生效，导出产物与预览同一份数据。

### 数据与管线

| 件 | 内容 |
|---|---|
| 数据 | `MediaClip.mask?: MediaClipMask`；`MaskStroke { mode:'hide'|'restore'; radiusPct; points[{x,y}] }`，坐标**归一化到画面**（0..1，与分辨率/缩放无关）；`normalizeMediaClipMask` 夹半径 0.1..50、点 [0,1]、上限 200 笔/2000 点/笔，空 → undefined 整键不落盘 |
| 羽化 | `MediaClipMask.featherPct`（0..20 = 画面宽度的百分比；0/缺省 = 硬边不落盘）；光栅化最后一步用 `ctx.filter = blur(featherPct/100 × 宽)` 把整张 mask 自绘一次 → **预览 CSS mask 与导出 PNG 是同一张图**，柔边程度天然一致；`applyMaskFeather` 越界夹 0..20，非法值不动（硬边零回归） |
| store / CLI / MCP | `setMediaClipMask(id, mask|undefined)`（同值不产生撤销步、空则删键）；CLI `clip.mask { id, mask|null }`；MCP 工具 `clip_mask` |
| 预览 | 媒体元素上按 `clip.mask` 生成 CSS mask（`mask-image/-webkit-mask-image` + `mask-size:100% 100%` + `mask-mode:alpha`）；mask 变化重建 blob URL 并 revoke 旧值，卸载回收；**无 mask 时媒体元素样式与旧版逐键相同** |
| 画笔 | 媒体段检查器「遮罩」分区：进入/退出画笔、笔刷半径 0.5..20%、抹掉/擦回、清空、笔画数；预览上 `MaskPaintLayer` 采点（归一化、0.0025 抽稀、单笔 ≤2000 点），松手**一次写入 = 一个 revision**，Esc/pointercancel 丢草稿，画笔模式隐藏变换手柄防误触 |
| 导出 | 渲染侧 `maskRaster` 复用预览 `maskCapture` 的同一绘制函数（白底、hide=`destination-out`→RGB 黑 alpha 0、restore 白、圆头圆角、单点 arc；`lineWidth = 2·radius%·画布宽`）→ PNG 字节进 `ExportRequest.mediaMasks`；主进程写 `mask-<clipId>.png` 并把 `maskPath` 接到对应段；有遮罩强制多输入路径，mask 输入排在段输入之后，`overlayLabel = 段数 + 遮罩数` |
| 滤镜链（单轨不透明） | 段画面归一化后、fx 几何**之前**做 alpha 相乘：`format=rgba → alphaextract → [mask]format=gray,scale=W:H → blend=all_mode=multiply → alphamerge`，再 `color=black` 叠底 + `trim/setpts/format=yuv420p` 收尾（隐藏区域变黑，段长不变） |
| 滤镜链（多轨/透明） | 同一段链但**不合黑底**：保留 RGBA，隐藏区域变透明露出下层轨道 |

**作用阶段口径**：遮罩在"段画面归一化到画布之后、片段 transform（缩放/位移/旋转/关键帧/镜像）之前"生效，
与预览把 mask 挂在媒体元素上（CSS transform 之前）一致 —— 有几何变换的片段两边跟着一起动。

### 真机踩坑（已锁进测试）

1. **`alphamerge` 取两路较长者**，不是"按第一输入结束"：无界 `-loop 1` 会把 1s 段拖成 90 帧。
   → mask 输入只喂 1 帧（`-loop 1 -framerate <fps> -t <1/fps>`），靠 framesync `repeatlast` 补齐。
2. **`overlay eof_action=endall` 会少一帧**（输出 EOF 在最后一帧 PTS，后续 `fps=` 少一帧：
   1s/30fps 变 29 帧）→ 黑底供帧 + `eof_action=pass:shortest=0` + `trim=end=<段长>` + `setpts`，
   实测单段 30 帧、两段拼接 60 帧且第二段入点不偏移。
3. `format=gray` 取**亮度**：hide 笔画必须落在 RGB 黑（alpha 0 或 255 都行），restore 白 —— 预览与导出共用
   `applyStrokesToContext` 保证同语义。

## M8-E 外部 matte（图片 / 视频）· 已完成（P0 泛化，零 AI/零新依赖）

目标：把手绘遮罩的「PNG → alpha 相乘」管线泛化为**通用 matte 输入**，支持用户导入外部图片或视频 matte
（AI 抠像的前置管线，也是零依赖退路；本轮不做任何推理/新依赖）。

### 数据与入口

| 件 | 内容 |
|---|---|
| 数据 | `MediaClip.mattePath?: string`（**绝对路径**，与素材同一惯例）+ `MediaClip.matteKind?: 'image'|'video'`（显式优先，缺省按扩展名：`.png/.jpg/.jpeg/.webp/.bmp/.tif/.gif/.avif` = image，常见视频容器 = video，其余要求显式 kind）；`normalizeMediaClip` 已归一化；`OverlaySegment.mattePath/matteKind` 透传 |
| store / CLI / MCP | `setMediaClipMatte(id, { path, kind } | undefined)`（同值不产生撤销步、空则删两键）；CLI `clip.matte { id, path|null, kind? }`（path 必须绝对路径且文件存在，扩展名判断不出时要求显式 kind）；MCP 工具 `clip_matte` |
| UI | 媒体段检查器「外部 matte」分区：导入（`media:pickMatte`，dialog → fs.stat → 扩展名判类型，图片顺带 ffprobe 探尺寸）/ 移除 / 当前文件名与类型 chip / 明确提示「仅导出生效（预览仍显示原片）」 |
| 导出 | matte 与 mask 可同时存在：输入顺序 `各段媒体 → 各段 mask → 各段 matte → 帧流/透明层 → 水印 → 音频`，`overlayLabel = 段数 + mask 数 + matte 数`；段链先 mask 再 matte 做 alpha 相乘（乘法可交换，语句顺序由测试锁定） |

### 视频 matte 对齐口径（本轮唯一重点）

- 输入：`-i <matte>`（不加 `-loop`）。
- 段链预处理（**帧索引**，不用 `trim=end=秒`）：
  `[matteIdx:v]fps=<输出fps>,trim=start_frame=<round(源入点×fps)>:end_frame=<round(源出点×fps)>,setpts=PTS-STARTPTS,format=gray,scale=W:H[mm]`
  其中 `frameCount = round((sourceOutSec - sourceInSec) × fps)`（无变速时 = 段输出帧数）。
- 为什么用帧索引：研究文档 4.3 实测「等长 matte + `trim=end=<秒>` → 输出多 1 帧」（边界帧含在 PTS=end 上）；
  `trim=end_frame=<N>` 把帧数钉死，本机 e2e 断言等长 1s/30fps 输出 **30 帧**（不多 1 帧）。
- 短 matte（如 10fps 分析网格 1s vs 源 2s）：`fps` 先重采样、`trim` 只取可用帧，剩余部分由 framesync
  `repeatlast` 补齐；e2e 断言 2s 成片 **60 帧**、末帧左半仍被遮罩。
- **显式拒绝（可读错误，不静默错位）**：视频 matte + 变速段 / + 转场切点（含该段右侧紧邻切点，转场会用
  扩展手柄区间取帧）/ 用于图像片段。静态图 matte 不受这些限制（等同手绘遮罩）。
- 静态图 matte 沿用 mask 的输入写法（`-loop 1 -framerate <fps> -t <1/fps> -i` + 1 帧 repeatlast）。
- 作用阶段与 mask 相同：段画面归一化后、fx 几何变换之前（随画面缩放/位移/旋转）。

## M8-F AI 人像抠像（ONNX Runtime + Selfie Segmenter）· 已完成（P1）

目标：给 M8-E 的外部 matte 管线接上**内置 AI 来源** —— 点一下按钮，主进程逐帧推理生成 matte 视频，
自动写回 `MediaClip.mattePath`（`matteKind='video'`），导出直接复用同一条段链（零新增滤镜逻辑）。

### 依赖与模型选型

| 件 | 内容 |
|---|---|
| 运行时 | `onnxruntime-node@^1.31.1` 放 **optionalDependencies**（N-API 预编译 win-x64 CPU 版）。`src/main/aiMatte.ts` 用 `loadOnnxRuntime()` 惰性 `require`；缺失/ABI 不匹配 → `{ ok:false, reason }` → `AI_RUNTIME_MISSING` / `AI_MODEL_LOAD_FAILED` 可读错误，**不崩溃、不静默降级** |
| 构建 | `electron.vite.config.ts` 主进程 `rollupOptions.external = ['onnxruntime-node','onnxruntime-common']`（原生模块不能 bundle） |
| 模型 | MediaPipe **Selfie Segmenter 256²**（Apache-2.0，462,352 B）：`scripts/fetch-matte-model.mjs` 取回 → `resources/models/matte/selfie_segmenter.onnx`（gitignored 可选资产；`check:env` 有则打印、无则警告；`SOCUT_MATTE_MODEL_PATH` 可覆盖，测试/离线部署用） |
| 选型纪律 | RVM（GPL-3.0）、RMBG（非商用）按 `docs/research/ai-matte-evaluation.md` 明确排除；MODNet / IS-Net 见未完成 |

### 生成任务（`src/main/aiMatte.ts`，685 行）

- 链路：FFmpeg 解码源窗口（`-ss/-t` + `fps=<输出fps>` + `scale=<matteW>:<matteH>:flags=bicubic` → rawvideo **rgba** pipe）
  → 逐帧 `detect`（RGBA→256² 双线性 → NCHW RGB/255 → `session.run` → alpha 256² → 双线性回 matte 尺寸 0..255）
  → 灰度 rawvideo pipe → FFmpeg 编 **FFV1 gray** 到 `userData/matte/<cacheKey>.mkv`。
- matte 尺寸：`matteSizeFor(源宽,源高)` = 长边 **512**、双偶数 —— 模型输入固定 256²，与源分辨率解耦
  （4K 源与 720p 源推理成本相同，只差解码/缩放）。
- 缓存键：`sha256(源路径 + 文件大小 + mtime + 源入出点 + fps + 模型 sha256 + matte 尺寸)`；
  命中直接返回 `{ status:'cached', path }`（**不启推理、不起 FFmpeg**）；同片段作业在跑时复用 jobId。
- 进度/取消：jobId = `matte-<clipId>`，走既有 export job 事件（`framesDone/framesTotal`）；
  取消复用 `export.cancel`（同时终止 decode/encode 子进程 + watch 轮询），**失败/取消清理半成品**、不写 `mattePath`。
- 错误码：`BAD_REQUEST` / `MEDIA_NOT_FOUND` / `MEDIA_NOT_VIDEO` / `AI_RUNTIME_MISSING` / `AI_MODEL_MISSING` /
  `AI_MODEL_LOAD_FAILED` / `AI_INFER_FAILED` / `CANCELLED` / `FFMPEG_MISSING`。
- 测试注入点：`setMatteDetectorFactoryForTests`（假 detector 也能跑真 FFmpeg 解码/编码/缓存/进度，不把 31MB 运行时塞进每条用例）。

### 接入与入口

- UI：媒体检查器「AI 抠像」分区 —— 状态 chip（就绪 / 模型未就绪 / 运行时未就绪 + 原因）、生成按钮、
  `正在生成 matte… n/N 帧`、取消；完成后 `setMediaClipMatte(id, { path, kind:'video' })`，
  沿用 M8-E 的「仅导出生效（预览仍显示原片）」口径。preload 缺 `aiMatte` 通道时降级成「运行时未就绪」而不是抛异常。
- CLI / MCP：`ai.matte { id }`（等到完成才返回 `{ id, jobId, mattePath, cached }`；变速片段直接 `BAD_PARAMS`）、
  `ai.matte.status`；MCP `ai_matte` / `ai_matte_status`；已写进 `docs/cli.md` 与 `docs/mcp.md` 工具表。
- 导出：AI matte 与源**同区间、同 fps** 生成 → 与段等长，直接走 M8-E 的帧索引段链，无需额外对齐；
  仍受 M8-E 显式限制（变速片段 / 转场切点 / 图像片段拒绝，可读错误）。

### 打包与分发

- `electron-builder.yml`：`files` 白名单带 `onnxruntime-node`（package.json + dist + win-x64 dll/binding）与
  `onnxruntime-common`；排除 darwin/linux/arm64 与 DirectML/dxcompiler（≈36MB 不用）；`asarUnpack` 显式解出
  `onnxruntime.dll` + `onnxruntime_binding.node`（实测 electron-builder smartUnpack 会把该可选包整体解到
  `app.asar.unpacked`，只会是 files 白名单内的 win-x64 文件）；模型走 `extraResources: resources/models/matte → models/matte`
  （可选资产，缺失只 warn）。
- 体积增量：`onnxruntime.dll` **31,736,672 B** + `onnxruntime_binding.node` **358,200 B** + 模型 **462,352 B**。
- 打包烟测：`npm run smoke:packaged:ai` —— 用 `release/win-unpacked/Socut.exe` 的 `ELECTRON_RUN_AS_NODE=1`，

### 真机踩坑（已锁进测试）

1. **进度广播需要 `BrowserWindow.getAllWindows`**：`applyAiMatte(req, null)` 走进程级广播，
   Electron 测试桩缺静态方法会 `TypeError` → `tests/aiMatte.test.ts` 的 electron mock 必须带 `static getAllWindows`。
2. **取消用例必须用缓存未命中的区间**：同源同区间第二次调用是 `cached`，根本不会起作业，
   `waitForAiMatteJob` 永不 settle（第一版 30s 超时就是踩这个）。
3. **纯色帧对真模型是合法全 0**（Selfie 找不到人）：真模型断言改用**合成人像帧**（椭圆头 + 躯干色块），

4. `ELECTRON_RUN_AS_NODE` 模式下 Electron 仍支持 asar（`fs.existsSync(app.asar/...)` 为 true），

## M8-G 反向遮罩与笔刷快捷键 · 已完成（P0 增强）

补齐 M8-E 未完成表里的两项低风险增强（数据仍是静态遮罩，不引入关键帧）：

| 件 | 内容 |
|---|---|
| 数据 | `MediaClipMask.invert?: boolean`：只有显式 `true` 才落盘（`false`/缺省整键不写，旧工程写回逐字节一致）；`normalizeMediaClipMask` 归一后键序固定为 `strokes → featherPct → invert` |
| 光栅化 | `applyStrokesToContext(..., featherPct, invert)` 在羽化之后加一步 `xor + 不透明白 fillRect`：结果 alpha = 1 − 原 alpha、RGB = 255×新 alpha（白=可见/黑=透明同步）。预览 CSS `mask-mode: alpha` 与导出 `format=gray`（取亮度）两条路仍读同一张 PNG |
| 预览 | `MediaPreviewLayer` 的 mask 内容签名改为序列化整份 `mask`（此前只序列化 `strokes`，改羽化不会重新光栅化 —— 顺手修掉的隐患），`invert` 变更立即重出 blob URL |
| 导出 | `maskRaster.paintMaskStrokes` 把 `invert` 传进同一份光栅化函数；`ExportRequest.mediaMasks` 的 PNG 已含反向，主进程段链零改动（`alphamerge` 语义不变） |
| UI | 检查器「遮罩」分区新增「反向遮罩」开关（与羽化互相保留，改任一项都不丢另一项）；画笔层新增 `[` / `]` 快捷键按 1% 画面宽步进调笔刷（clamp 0.5..20，与滑杆同一 `MASK_BRUSH_RANGE`，不打断当前笔画） |
| 笔画继承 | `MaskPaintLayer` 提交新笔画时继承该段已有 `featherPct` / `invert`（此前画第二笔会把羽化/反向悄悄丢回白底） |

**为什么不用 `destination-out` 直接反相**：Canvas2D 没有"反转 alpha"的合成模式；
`xor` 与 `globalAlpha = 1` 的白色源合成时，按规范 alpha 结果正好是 `1 − dA`，
且预乘颜色 = 白色 × (1 − dA)，所以 RGB 与 alpha 天然同步（真机 Chromium 探针实测：
`[[255,255,255,255],[255,255,255,255],[0,0,0,0],[0,0,0,0]]`，左半由透明变白、右半由白变透明）。

**取证**

```

  src/renderer/src/render/maskRaster.test.ts src/renderer/src/components/MaskPaintLayer.test.tsx \
  src/renderer/src/panels/MediaClipInspector.test.tsx src/renderer/src/components/MediaPreviewLayer.test.tsx \
  src/renderer/src/render/exportRunner.mask.test.ts
# 10 + 16 + 8 + 14 + 44 + 31 + 6 例全绿：
#   归一化：invert 只有 true 落键、false/非法丢弃；与 featherPct 共存键序稳定
#   光栅化：羽化后出现一次 xor fillRect；invert=false 无 xor；导出光栅化与预览逐操作一致
#   画笔层：第二笔继承 feather/invert；[ / ] 步进 ±1% 且 clamp 0.5..20；其它键不触发
```

反向 + 转场只有 argv/光栅化层断言、无真机观感 e2e。
