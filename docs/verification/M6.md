## M6-A 贝塞尔缓动基座 · 已完成

`src/shared/bezier.ts`（纯函数，无 DOM）：

| 函数 | 口径 |
|---|---|
| `normalizeBezier(value)` | 4 个有限数；x 夹 [0,1]（CSS 要求，保证 x 单调、解 t 唯一）；**y 越界直接拒绝**（过冲是产品禁区，不做"夹一下再用"的静默降级） |
| `bezierAt(bezier, x)` | Newton 迭代解 `x(t)=x`（8 次），失败退二分（40 次），返回 y；输入/输出夹 [0,1] |
| `bezierSamples` | 折线采样（UI 画曲线 / 测试单调性） |
| `isBezierOvershootFree` | 64 点采样**未夹取**原始输出：y ∈ [0,1] 且单调不减（与 `easing.isOvershootFree` 同一判据） |
| `acceptBezier` | 归一化 + 单调校验；非法/过冲返回 null 由调用方回退线性 |
| `bezierToCss` / `bezierEquals` | 画图字符串 / 默认值判断 |

**取证**：`tests/keyframes.test.ts` 覆盖反解精度、端点、x 夹取、y 过冲拒绝、非法输入。

## M6-B 关键帧数据模型与求值 · 已完成

`src/shared/keyframes.ts`：

- 参数清单 `CLIP_PARAM_IDS`：`opacity` / `offsetXPct` / `offsetYPct` / `scalePct` / `rotationDeg`，
  每个参数带 `min/max/defaultValue/step`（schema 归一、UI 夹取、求值兜底共用一份）。
- `KeyframeTrack { param, points }`；`KeyframePoint { t(0..1), value, easing, bezier? }`。
- `normalizeKeyframeTracks(raw)`：未知参数丢弃、空轨道丢弃、按 t 升序、同 t 后来者胜、
  值夹到参数范围、点数上限 `KEYFRAME_MAX_POINTS=32`、custom 曲线非法回退 linear、全非法返回 undefined（整键不落盘）。
- `keyframeValueAt(track, t)`：端点外保持首尾值；分段插值，缓动取**本点**的 `easing`（作用于"本点 → 下一点"）。
- `resolveClipParams(tracks, t)`：返回片段在进度 t 的最终参数 + `hasAny`（渲染层据此走零开销旧路径）。
- `clipProgressAt(seconds, start, end)`：片段内进度，越界夹取、零时长返回 0。
- `upsertKeyframePoint` / `removeKeyframePoint` / `hasKeyframes`：UI 与 CLI 共用的纯编辑入口。

**schema**：`SubtitleClip.keyframes?`（可选字段，不动 `PROJECT_VERSION`）；`normalizeClip` 归一，
非法数据整键丢弃 → 旧工程 JSON 形状不变。

**store**：`setClipKeyframes(id, tracks | undefined)` —— 归一后逐字节比较（相同不产生撤销步）、
空数据删键、`revision + 1`（撤销一步 + 自动存档）。拆分时**左半段保留、右半段不继承**（内部切点与转场同一纪律）。

**CLI**：`clip.keyframes { id, keyframes | null }`、`clip.keyframes.reset { id }`。

## M6-C 渲染接线（字幕条）· 已完成

`src/renderer/src/render/renderer.ts`：

- 每帧按 `progress = (frame - startFrame) / (endFrame - startFrame)` 求值；
- `hasAny === false` → 不产生任何额外状态切换（**逐像素与旧版一致**）；
- 有 `offset/scale/rotation` 时：以**实际绘制内容**的几何中心（`contentAnchorOf`，与擦除线同一口径）为原点做 translate/rotate/scale；
- 不透明度：`layers.drawBar/drawRule/drawText` 新增 `alphaMul` 参数，逐层乘进绘制 alpha（不用 `ctx.globalAlpha`——
  它会覆盖逐字渐显/擦除窗口的透明度）。

**取证**：`tests/keyframes.test.ts` 用录制式假上下文断言：
- 无关键帧 → 0 次 translate/rotate/scale；
- 不透明度 0→1 线性，帧 60/150 → 逐字 alpha = 0.4；
- `offsetXPct=10 / scale=50% / rotation=30°` → translate = 内容中心 + 192px、scale 0.5、rotate ≈ π/6，收尾回到 `-anchor`。

## M6-D 时间轴关键帧菱形 · 已完成

`src/renderer/src/timeline/ClipCard.tsx`：

- 取出所有参数轨关键帧的 `t` 并集（0..1 片段进度，毫秒级去重），在字幕条上画菱形；
- 位置 = `t × 条宽`，两端夹到 `[2px, 条宽-2px]`，不会溢出到相邻片段；
- **点击菱形 = 跳到该关键帧在时间轴上的位置**（`片段入点 + t × 时长`，吸附帧边界 + 播放中先暂停）——
  菱形按下时 `stopPropagation`，不会误触发整条拖动；
- 无关键帧时 0 个 DOM 节点（零开销）。

**取证**

## M6-D 命中测试跟随关键帧变换 · 已完成

原问题：`hitTestClips` 按**未变换**的布局盒判定，关键帧把条块位移/缩放/旋转后，
用户点到"看到的位置"却选不中（或点到空白却选中）。

修法（`src/renderer/src/render/hitTest.ts`）：
- 锚点计算 `contentAnchorOf` 从 renderer 移到 `layers.ts`（绘制与命中测试共用同一份口径）；
- 命中前把画布点做**逆变换**回片段局部坐标：绘制是 `p' = A + S·R·(p − anchor)`（A = 锚点 + 画宽/高百分比位移），
  命中用 `p = anchor + S⁻¹·R⁻¹·(p' − A)`，无旋转时省掉三角计算；
- 不透明度 < `HIT_MIN_OPACITY`（0.02）视为不可点：完全透明的像素不算"看得见"；
- 无关键帧时 `params.hasAny = false`，**原样返回原点**，旧行为逐像素不变（有测试锁定）。

**取证**

```
npx vitest run tests/hitTest.test.ts
# 22 例全绿（原 17 例 + M6 新增 5 例）：
#   位移 −10%：条块左缘外 100px 的空白区变成可点（未挂关键帧时仍是空白）
#   位移 +10%：右缘外 100px 同理；平移量 = 画宽 10%（192px @1080p）
#   缩放 200%：距中心 0.75 条宽处由"条外"变"条内"
#   旋转 90°：条高方向（> 半条高）的点由不命中变命中
#   不透明度 0 不可点、0.5 照常可点；关键帧片段在时间区间外仍不命中
```

## M6-E 媒体段关键帧 · 已完成（预览 + 导出同源）

目标：让**视频/图片段**也能按时间改几何（位移/缩放/旋转/不透明度），预览 DOM 与导出 FFmpeg 同一口径。

| 件 | 内容 |
|---|---|
| 数据 | `MediaClip.keyframes?: KeyframeTrack[]`（与字幕条同一套 `shared/keyframes` 模型，`t` = 片段内进度）；`projectSchema` 读盘归一（未知参数/非法点丢弃，缺省整键不落盘） |
| 语义 | 轨道存在 = **绝对覆盖**同名的静态 `video` 字段（`scalePct↔scalePercent` 等），没轨道的参数仍用静态值；`opacity` 媒体段没有静态字段，缺省 1 |
| 求值 | `shared/mediaClipKeyframes.ts`：`mediaFrameParamsAt` / `mediaKeyframeCssAt`（预览 CSS，顺序与静态 `mediaVideoTransform` 一致）/ `mediaParamExpr`（导出表达式，按 48 点采样折线，可切时间变量名）/ `mediaKeyframesActive` |
| 预览 | `MediaPreviewLayer` 给每段加一层 `.stage__media-keyframes` 包裹 div，`tick()` 逐帧命令式写 `transform/opacity`（不走 React state）；元素自身的静态 transform 在挂关键帧时不再应用（避免被覆盖的参数重复生效）；包裹层 opacity 与"切段可见性/转场"的 opacity 相乘 |
| 导出 | `buildMediaClipVideoFx` 增加关键帧分支：`scale=...:eval=frame`、`rotate=angle='expr':ow/oh=<整段最大包围盒>`、`overlay=x/y=表达式`、不透明度用 **8×8 白底 → geq(alpha) → alphaextract → 放大 → alphamerge**（掩膜空间均匀，8×8 足够，避免 1080p 逐像素 geq） |
| 面板 | `KeyframePanel` 泛化为 `KeyframeTarget`（字幕条/媒体段共用），媒体段传 `onCommit=setMediaClipKeyframes` 与 `defaults`（打点初始值取静态 video 值）；`MediaClipInspector` 新增「关键帧」分区 |
| store/CLI | `setMediaClipKeyframes`（归一 + 同值不产生撤销步 + 全空整键删）；`clip.keyframes` / `clip.keyframes.reset` 命令按 id 先查媒体段（返回 `kind: 'media' \| 'subtitle'`） |

### 真机踩坑（已锁进测试）

1. **关键帧会被"默认视频直通链"吞掉**（导出接线测试抓到的真 bug）：`singleTrackVideoChains` /
   `multiTrackVideoChains` 原来只看 `isDefaultMediaVideo(seg.video)` 决定走不走 fx 链——
   只挂了关键帧、静态几何全默认的段会走直通链，关键帧**静默失效**。
   修法：统一 `needsVideoFx(seg) = !isDefaultMediaVideo(seg.video) || mediaKeyframesActive(seg.keyframes)`，
   三处判定（单轨/多轨/标签选择）共用；并加"导出 argv 接线"测试（`-filter_complex` 里必须出现
   `eval=frame`），避免以后又被静默吞掉。
2. **`rotate` 在 FFmpeg 9 没有 `eval` 选项**（传 `eval=frame` 直接 `Option not found`）；`angle` 带 T 标记，
   表达式按帧求值即可。
3. **`geq` 的时间变量是大写 `T`**（overlay/scale/rotate 是小写 `t`）；且 `geq` 也没有 `eval` 选项。
4. **alpha 掩膜不能直接用 `format=gray`**：那取的是亮度不是 alpha，动画会"看起来生效、实际永远不透明"；
   必须 `alphaextract` 取 alpha 平面（再 `format=gray` + 放大）。
5. `geq` 输出后要显式 `format=rgba` 才能让 `alphaextract` 选到格式（否则报 "could not choose their formats"）。
6. 旋转包围盒在构建期用**整段采样最大值**定成固定 `ow/oh`（表达式无法在构建期取极值）。
